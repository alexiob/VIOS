# VIOS VDP rebase evaluation: vendored VDP 1.04 against agon-vdp 2.16.0

**Status:** evaluation only (2026-10-19). No firmware changed, the board was
not touched.

**Context:** The ESP32 firmware (`firmware/esp32-vios`) vendors the Agon VDP
1.04 and vdp-gl 1.0.3, with VIOS changes on top. AgonPlatform agon-vdp
2.16.0 is current. The owner has already decided to update the eZ80 to MOS
3.0.2, which supports VDP 1.04 and up, without waiting for a VDP rebase
(untethered boot spec, `2026-10-19-vios-untethered-boot.md`). This document
answers a separate question: should the vendored VDP be rebased onto 2.16.0?

Hard constraint: the GUI display server (`lib/vios-vds`) composes straight
into the fabgl framebuffer and must keep 60 fps vblank frames
(acceptance on `firmware-untethered-7`: frame work 4.0 ms, vblank start
91 us).

### 1.4 The larger dependency: VIOS code that reaches into the VDP

The 243-line patch (230 added, 13 removed) is what a rebase must re-apply. What it must *re-validate*
is bigger: about 5,000 lines in `include/vios_*.h` and `lib/vios-vds` that
use VDP globals and vdp-gl internals directly, from inside the `video.ino`
translation unit.

| Symbol (uses) | Owner | Used by |
|---|---|---|
| `canvas` (27), `palette` (9), `colourLookup` (3), `videoMode` (8), `ttxtMode` (6), `fontW`/`fontH` (7), `getVGAColourDepth` (7), `set_mode` (4), `plotCharacter`, `processor`, `send_packet` | agon-vdp globals (`graphics.h`, `video.ino`) | `vios_console_vdp.h`, `vios_gui.h`, `vios_g0_probe.h`, `vios_bridge.h` |
| `VDPSerial` (13), `DBGSerial` (8) | agon-vdp | `vios_bridge.h` writes `FA`/`FE`/`FC` packets straight to the UART |
| `VdpRows` → `VGAPalettedController::m_viewPort`, `m_viewPortVisible`, `sgetScanline` (protected) | vdp-gl internals | `vios_console_vdp.h` (4 bpp console blitter), `vios_frame.h`, `vios_gui.h` (`vds_init` gets the row table) |
| `FONT_AGON_DATA` (4) | vdp-gl | `vios_gui.h`, console |
| `vios_vblank_hook` | the vdp-gl patch | `vios_frame.h` |

`VdpRows` is not a vdp-gl edit. It is a subclass cast that reaches protected
members of `VGAPalettedController` to get the framebuffer row table, and it
assumes single buffering (`m_viewPort == m_viewPortVisible`). The whole
4 bpp console and GUI path rests on it. A vdp-gl version that renames,
privatises or double-buffers those members breaks VIOS even when the 21-line
ISR hook re-applies cleanly.

**Observation:** VIOS uses little of the VDP's VDU layer. The GUI composes
into the framebuffer through `vios-vds`, the console renders through its
own blitter, and MOS's output is filtered during the MOS phase. The live
dependencies are the serial transport (`VDPSerial`, `send_packet`, the
stream processor's read functions), the keyboard path, mode setting, and
the vdp-gl VGA16 driver.


## 2. What agon-vdp 2.16.0 changed in those areas

Sources: clones of `AgonPlatform/agon-vdp` (`v2.16.0` = `c7ac293`,
2026-04-19), `AgonPlatform/vdp-gl` (`all-the-plots` = `ac2dd59`, 2026-04-19)
and `AgonPlatform/agon-mos` (`v3.0.2`), read but not built. Research notes:
the side-session notes folder, `vdp-2.16-research.md`. Items marked
*inferred* were not confirmed in source.

### 2.1 Size of the gap

| | agon-vdp `video/` | vdp-gl |
|---|---|---|
| Relation to the VIOS base | `61888ab` is an ancestor of `v2.16.0` (`git merge-base` returns it) | `48a0b9a` is **not** an ancestor: its tree equals the squash merge `17be337` on main |
| Commits since | 479 touching `video/` (399 non-merge), 600 in total | 92 (75 non-merge) |
| Diff | 46 files, +15,704 −2,869 | 37 files, +7,333 −585 |

The VIOS patch (§1.2) is about 1.5 % of the upstream change in `video/`.

### 2.2 Build and toolchain

| | VIOS (1.04) | 2.16.0 |
|---|---|---|
| Platform | `espressif32@6.3.0` (arduino-esp32 2.0.9) | `espressif32@6.6.0` (arduino-esp32 2.0.14); comment: 6.9.0 costs 0.5 KB more internal RAM |
| vdp-gl | 1.0.3 | `all-the-plots` |
| Flags | `-Os`, C++11 | `-O2`, C++17 |
| Libraries | ESP32Time | ESP32Time, `robtillaart/CRC` |
| Partitions | default (two ~1.25 MB app slots) | default |

`vios-vds` and the `include/vios_*.h` headers would have to compile as C++17
and under `-O2` (larger code; VIOS's app slot is capped at 1,310,720 bytes
and embeds the resident image).

### 2.3 Source layout and main loop

- `graphics.h`, `cursor.h` and `viewport.h` are gone. Text and graphics state
  lives in `class Context` (`context.h`, `context/{cursor,fonts,graphics,viewport}.h`),
  with save/restore stacks (`VDU 23,0,&C8`). `gfg/gbg/tfg/tbg`, paint
  options, `activeCursor` and the font size are context members;
  `plotCharacter` became `Context::plotString` and friends; `change_mode` is
  `changeMode()` in `agon_screen.h`.
- Still globals: `canvas`, `videoMode`, `palette`, `_VGAController`
  (`agon_screen.h`), `ttxtMode`, `colourLookup`.
- **The VDU parser moved to core 0.** `setup()` starts `processLoop` pinned
  to core 0 (priority 3); `loop()` only sleeps. `processNext()` now runs, in
  order: a vsync check on vdp-gl's `frameCounter`, an event queue, keyboard
  and mouse, cursor flash, and a state machine (active, waiting for frames,
  paged-mode pause, Ctrl-Shift pause).
- Keyboard: a key sets the KEYEVENT VDP variables, runs keyboard callbacks,
  and is queued; `processEventQueue()` sends the same 4-byte
  `PACKET_KEYCODE`. Line editing is still done by MOS (`mos_editor.c`).
- The text and mouse cursors are hardware sprites drawn in the scanline ISR.
- `vdu_buffered.h` grew by about 2,400 lines (callbacks, matrices,
  compression); buffers, tiles and Y-Modem use PSRAM.

### 2.4 Protocol, packet codes and flow control

- **Link:** unchanged. 1,152,000 baud, TX 2, RX 34, RTS 13, CTS 14, RX
  buffer 256, `COMMS_TIMEOUT` 200 ms (new `FAST_COMMS_TIMEOUT` 10 ms).
- **Flow control:** `setVDPProtocolDuplex()` (since 2.11.0) switches between
  `HW_FLOWCTRL_RTS` and `HW_FLOWCTRL_CTS_RTS`. The VDP starts half-duplex;
  MOS turns full duplex on by setting VDP variable `0x0101` with
  `VDU 23,0,&F8,1,1,1,0`. There are no packet acknowledgements.
- **MOS side:** MOS 3.0.0+ routes the eZ80's RTS/CTS pins to UART0 and sets
  `UART0_MCTL = 0x02` once; it never toggles RTS (*inferred*: "full duplex"
  then means the ESP honours a CTS line MOS keeps asserted).
- **Packets:** `0x00`–`0x09` unchanged; new `0x0A` `PACKET_ECHO` and `0x0B`
  `PACKET_ECHO_END` (2.12). Nothing in `0x0C`–`0x7F`; MOS 3.0.2 ignores codes
  above `0x09`. **No collision** with VIOS's `0x7A`–`0x7E` (`FA`–`FE`).
- **VDU 23,0 at 2.16.0:** `0A 0B 80–8C 90–96 98–9F A0 A1 C0–C4 C8 CA F2 F8
  F9 FE FF`. **Nothing in `E0`–`EF`**, so VIOS's `E0`–`E8` and its rule
  "any `E0`–`EF` ends the MOS phase" stay valid. Feature switches (duplex,
  keyboard and mouse state, echo `0x0110`) are VDP variables set with
  `F8`/`F9`, not new commands.

### 2.5 Firmware update (OTA)

- `updater.h` barely changed (+20 −4): `VDU 23,0,&A1` with 0 = unlock,
  1 = receive size, image and checksum then write with the ESP OTA API and
  restart, 2 = switch slot. 2.16 adds only "hide hardware sprites and cursors
  during an update" (they crashed `agon-flash`).
- Per the 2.16.0 release notes, `agon-flash` (v1.9) can update a VDP from
  1.04RC3 on, except from 2.8.0, 2.12.0 and 2.13.0; the web installer is
  the recommended route. VIOS does not use either.
- VIOS disables `&A1` under `VIOS_USB_MUX` and flashes app0/app1 from the Mac
  over USB. Re-enabling `&A1` is a VIOS decision, available on 1.04 today.

### 2.6 vdp-gl

- **VGA16 ISR:** still `s_scanLine += VGA16_LinesCount / 2` with
  `VGA16_LinesCount` 4, and still a `scanLine >= height` vsync branch (now
  also `frameCounter++`). The `vios_vblank_hook` call re-applies at the same
  place.
- **More ISR work per line:** palette signals come from
  `getSignalsForScanline()` (copper, per-line palettes) and
  `decorateScanLinePixels()` draws hardware sprites and cursors into each
  line. VIOS's black-bar work (`c11ee11`, `0b7bf97`) showed the line ISR has
  to refill every ~63.6 µs; extra ISR cost is the main display risk
  (*inferred*; measurable with the existing gap probe).
- **`VdpRows` survives:** `m_viewPort`/`m_viewPortVisible` are protected in
  `VGABaseController` (reachable from a `VGAPalettedController` subclass),
  `sgetScanline` is a public static. Double buffering is still opt-in via
  `setResolution(..., doubleBuffered)`, so the single-buffer assumption holds
  in mode 0 as VIOS sets it.
- **API breaks:** `m_packedPaletteIndexPair_to_signals` replaced by
  `packSignals()`, `m_signalList`, `updateSignalList()`; `setPaletteItem`
  moved to the base paletted class; the paletted controller constructor
  takes an extra argument. New `VGA64Controller`.
- `FABGLIB_MINFREELARGESTBLOCK` is **4,000** upstream (from 40,000,
  `40a16d4`), so VIOS's 24,000 patch becomes unnecessary or a raise.
- Framebuffers stay in internal RAM.

### 2.7 MOS 3.0.2 against VDP 1.04 (relevant to the decision already made)

MOS 3.0.2's release notes: works with VDP 1.04 or later, best with 2.14.1+.
MOS has no version check. At boot (`main.c`) it sends, in order:

1. `VDU 23,0,&80,1` (general poll) every 50 ms until a reply. VIOS starts its
   MOS phase on `&80`, so this still triggers it.
2. `VDU 23,0,&F8,1,1,1,0` (full duplex).
3. `VDU 23,0,&99,117` (is Shift held: skip the boot file).
4. `VDU 23,0,&86` (mode).
5. `VDU 23,0,&94,128` (palette read; a valid reply enables coloured CLI
   output).

On VIOS's 1.04 parser, `&F8`, `&99` and `&94` hit no `case`, and their
argument bytes are parsed as VDU codes. During the MOS phase those go
through VIOS's filter (`vdu.h`; `vios_mos_vdu_args` and `vios_mos_text` in
`vios_bootserve.h`): `1,1,1,0` are two VDU 1s with their argument and
vanish, `128` is not text and is dropped, and `117` (`u`) reaches the
Console window (*inferred* from the code, not run). Effects: one stray `u`
in the boot text, no Shift-to-skip, no coloured CLI. Full duplex is not
lost: VIOS already runs `HW_FLOWCTRL_CTS_RTS` unconditionally. None of this blocks path B.

## 3. Port plan

Two strategies were considered. **Rebase** = take `v2.16.0` and
`all-the-plots` as the new vendored base and re-apply §1.2. **Backport** =
keep the 1.04 base and copy in only the upstream pieces VIOS wants.

### 3.1 Rebase, per area

| Area | Work | Risk | Effort |
|---|---|---|---|
| Toolchain: 6.6.0, C++17, `-O2` | Rebuild VIOS headers and `vios-vds`; check app size against 1,310,720 with the embedded resident | Medium: `-O2` and 15 k more lines grow the image | 1 d |
| vdp-gl: vblank hook, ISR probe, reserve | Re-apply 21 lines; drop the 24 KB patch (upstream is 4 KB); check `VdpRows` and palette code against the new signal list | **High**: per-line copper and sprite work in the VGA16 ISR; the black-bar budget must be re-measured | 1 d port, 1–2 d board measurement |
| Main loop and tasking | Parser now on core 0 in `processLoop`; VIOS's loop hooks (bridge service, CPU pause, section timing, console tick, G0) must move into `processNext()` or the event queue. The frame task (core 1) and the parser then run in parallel, not by preemption on one core: every canvas and framebuffer access needs `vios_display_lock()`, not only `change_mode` | **High**: changes the concurrency model the GUI was accepted under | 3–5 d |
| Stream processor reads | Re-apply `vios_vdp_wait_running` in the read paths (more of them now: `FAST_COMMS_TIMEOUT`, state machine) | Medium | 1 d |
| VDU 23,0 `E0`–`E8`, MOS phase | Re-apply to `vdu_sys_video()`; no code collisions. The MOS-phase filter in `vdu()` must also pass 2.x's new MOS boot commands | Low | 1 d |
| Keyboard, GUI keys, line editing | `do_keyboard()` is gone: hook `vios_gui_key`, injected keys and `vios_line_key` into the event queue / keyboard callbacks | Medium | 1–2 d |
| Glyph-state cache, mode lock | `plotCharacter` and pen state are now in `Context`: rewrite `vios_glyph_state_valid`; `changeMode()` lock | Medium | 1 d |
| VIOS headers using VDP globals | `fontW/fontH` → `getFont()`, `tfg` etc. via context; `canvas`, `palette`, `videoMode` unchanged | Low–medium | 1 d |
| Memory | Mode 0 + GUI pools need ≥ 24 KB free largest block after mode set; 2.x carries more resident code and data (buffers, contexts, event queue) | **Unknown, can veto**: no figures exist; needs a build and a board measurement | 0.5 d to measure |
| Flow control | VIOS forces CTS/RTS; 2.x starts half-duplex. Either keep the force or have the resident set `0x0101` | Low | 0.5 d |
| ZDI, mux, mouse/terminal off, updater off | Re-apply `#if VIOS_USB_MUX` guards | Low | 0.5 d |
| Acceptance | GUI acceptance (frame work ≤ 4 ms, vblank start, no protocol errors), black-bar probe, editor repaint, untethered boot, host service | — | 2 d |

**Total: about 14–20 working days**, with two high-risk items and one
unknown that can stop it after the first week.

### 3.2 What VIOS would gain

| Gain | Real for VIOS? |
|---|---|
| Full-duplex flow control | **No.** VIOS already runs `HW_FLOWCTRL_CTS_RTS` from the start (`vdp_protocol.h`, `fabdaad`). 2.x makes it switchable and starts half-duplex. The open flow-control question (untethered boot §9 item 10, the stub driving RTS) is on the eZ80 side and is untouched by a VDP rebase. |
| `agon-flash` OTA | **No new capability.** `updater.h` is essentially the same as 1.04's; VIOS chose to disable `&A1` and flash over USB. It can re-enable it on 1.04. |
| Newer MOS 3.0.2 features | **Small.** Shift-to-skip the boot file, coloured CLI, no stray `u` at boot. VIOS hides MOS in the Console window and replaces it with the resident within seconds. |
| VDP graphics features (contexts, copper, hardware sprites, buffers, compression, layers, `VGA64Controller`) | Only for **MOS applications** running before or instead of VIOS. VIOS's own display is `vios-vds` drawing into the framebuffer. |
| Upstream fixes, newer arduino-esp32 | Some value, mostly for stock MOS use; nothing identified that VIOS needs. |
| Shared tooling (stock VDP version string, community support) | Modest. |

the GUI's timing, memory and concurrency untouched.

## 4. Recommendation

**Partial: no rebase now; backport the three MOS 3.0.2 boot commands.**

- A rebase costs 3–4 weeks, reopens the two things VIOS has just made
  acceptable on the board (vblank frame timing and the line-ISR budget), and
  changes the parser's concurrency model. Its headline gains are already
  present (CTS/RTS) or independent of the VDP version (OTA updater, eZ80-side
  flow control).
- The MOS 3.0.2 update the owner decided on works on 1.04. The §3.3
  backport (`&F8`/`&F9`, `&99`, `&94`) fixes its only visible degradations
  for 2–3 days. It can be done after the MOS update, when the boot can be
  watched on the board.
- **Revisit the rebase** if VIOS wants stock MOS applications to use 2.x
  graphics (buffers, sprites, copper), or if an upstream fix becomes
  necessary. Do it in this order, stopping at the first failure:
  1. Build 2.16.0 + VIOS's vdp-gl hook only; measure free largest block after
     mode 0 with the GUI pools on the board (needs ≥ 24 KB).
  2. Measure `vios_vga_isr_gap_max` and `vios_vga_isr_late` with the 2.x
     VGA16 ISR (sprites and copper idle).
  3. Only then port the main-loop hooks (§3.1).
- A vdp-gl-only bump is not recommended separately: avalonbits 1.0.3 is not
  an ancestor of AgonPlatform's vdp-gl, the API changed under the paletted
  controllers, and it brings the ISR risk without the MOS gains.
